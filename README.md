# WeFarm — tomato harvest simulator (AI Conf 2026 hackathon)

Harvest tomatoes with a real **Franka Panda** arm on a self-driving cart, in a **photoreal greenhouse** generated by World Labs (Marble), with **live MuJoCo physics** in the browser. Every session can be recorded and replayed for QA; recordings keep the full physics state so they can later be turned into training data.

```text
photo ─► World Labs Marble ─► splat (looks) ─┐
                                              ├─► browser: three.js + SparkJS + MuJoCo (WASM) ─► play · record · replay/QA
task layout (seed) ─► MuJoCo scene + plants ─┘
```

## Run it

Needs Docker (Colima on macOS).

```sh
docker compose up -d web          # Vite dev server on http://127.0.0.1:5180
```

Open <http://127.0.0.1:5180>. A loading screen shows each step with live progress. The page looks for the world package (the photoreal greenhouse) in a local copy at `data/worlds/crete-path/v2` first; if there is none, it downloads the public copy from `https://wefarm-aiconf-2026-assets.s3.us-west-2.amazonaws.com/worlds/crete-path/v2/` (7.3 MB for the default splat). A fresh checkout therefore needs no manual download. URL options: `?seed=7` (farm layout), `?splat=100k|500k|full`, `?world=<id>/<version>` (e.g. `crete-path/v2`), `?world=<url>` (an exact package folder), or `?world=none` (plain ground).

## Controls

| Input | Does |
| --- | --- |
| Click a tomato | The open gripper glides to just above it (the cart drives closer if needed) |
| W / S | Hand forward / back along the path |
| A / D | Hand left / right (towards a row) |
| R / F | Hand up / down |
| Q / E | Turn the gripper |
| Space | Open / close the gripper |
| [ / ] | Cart to the previous / next stop |
| H | Hand back to the ready pose |
| C | Camera: orbit (drag) → head → wrist |
| P | Show or hide the photo's own plants |

Picking: click a red tomato, press **F** to lower until the fingers surround it, **Space** to close (the tomato snaps off when pulled), **R** to lift, **S** to bring it back over the basket (or press **H**), **Space** to drop. A ripe tomato in the basket scores.

## Record, replay, QA

- **● Record** resets the scene and records; **■ Stop & save** downloads `wefarm-session-<time>.jsonl.gz`.
- **Replay…** loads a recording: play, scrub, jump to events, then **✓ Pass / ✗ Fail** with notes (downloads a small review JSON).
- Format (schema version 0, JSON Lines, gzip): a header (world, task layout and seed, scene hash, rates), one line per 50 Hz control step (operator command, actuator targets, joint positions `qpos`, which stems still hold), event lines (detach, harvested, dropped), and the full MuJoCo state once per second. See `web/src/recording/sessionRecording.ts`.

## Share it

`docker compose run --rm web npm run build` writes a static site to `web/dist/`. The static site loads the world package from the public bucket (or a `?world=<url>` you choose), so `dist/` stays small. Any static file host can serve `dist/`. Nothing is hosted by default.

## What's inside

| Path | What |
| --- | --- |
| `web/src/farm/` | Seeded layout of plants, trusses, tomatoes, and the cart |
| `web/src/sim/` | MuJoCo scene generator and simulation core (IK teleop, tomato detach, harvest detection); runs in Node too (`node --experimental-strip-types tools/simulationCheck.ts`) |
| `web/src/render/` | three.js drawing of MuJoCo geoms, generated plants, the Marble splat with plant erasing |
| `web/src/teleop/`, `web/src/recording/` | Keyboard/mouse control; recording and replay |
| `web/public/models/franka_emika_panda/` | MuJoCo Menagerie Panda, pinned (see `SOURCE.txt`, Apache-2.0) |
| `src/wefarm/` | Python: World Labs client with budget guard, world-package builder (`jobs` service) |
